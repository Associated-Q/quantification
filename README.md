# 技术分析工作台

把五本技术分析经典、一位 UP 主的公开问答与评论，做成**可检索、可溯源、可回测**的个人研究工具。

它不预测行情，也不推荐你买什么。它做五件事：

1. 把书和观点变成能查的知识库，每条结论都能翻到原书页码；
2. 把书里的规则写成代码，用真实成本模型回测，告诉你这套规则历史上到底赚不赚钱；
3. 每天盯住你的自选，按规则给出「规则评分」和「相对目标仓位的加减手数」；
4. 用一个 100 万的模拟盘把建议落地执行，逐日记录，让时间检验它；
5. 在个股 K 线上按规则画出小/中/大三档浪型与斐波那契回撤位，并可以让 AI 在候选结构里选出主数法。

> 仅供个人研究。所有输出都不构成投资建议。

> **仓库内容**：只提交代码、文档与测试。`.env`（模型密钥）、书籍原文与检索索引、行情数据库、日志、备份和扫描件均不纳入版本控制；克隆后按「开始使用」在本地生成。配置项见 `.env.example`。  
> 本次浪型/AI 选浪/交易计划改动的审阅说明见 [REVIEW.md](REVIEW.md)。

## 三、K 线浪型与 AI 选浪

个股详情页的 K 线图上会叠加两样东西：**多级别浪型**和**斐波那契回撤位**。

**尺度怎么定。** 不是固定浪级，而是按当前图的周期和波动率自适应：基础阈值
`2.5 × ATR14 ÷ 现价`，夹在 3%~8%；再取三档 `小 = base`、`中 = 1.8×base`、
`大 = 3.2×base`（上限 25%）。用的是当前周期已加载的 K 线：日线图表会按需只读翻页到
最多约 1600 根（不写回回测库）、周线约 740 根、月线 175 根、分钟线 800 根。所以日线的
"大级别"不等于周线的"小级别"，两者不保证对齐。

**从哪里画起。** ZigZag 从加载序列的第一根 K 线向右扫；同一级别内贪心分段、
结构不重叠（上一组浪5 的终点就是下一组的起点），不同级别允许嵌套。只有同时通过
五浪三条铁律和比例校验（浪2 回撤 23.6%~95%、浪4 回撤 10%~61.8%、浪3 ≥ 最长推动浪的
1.2 倍）的结构才会以彩色浪组画出。当前评分用的那组另有要求：终点在最近 15 根内、
现价偏离浪5 不超过 10%、且不存在跨度接近的其他数法。

**没通过校验怎么办。** 不画彩色浪线，只用灰色虚线标出候选数法，并在图例里写明
真实原因（例如"结构已陈旧，超过 15 根"）。斐波那契位则退回最近一段已完成波段，
并明确标注来源，避免把普通波动说成数浪结果。

**放宽候选。** 有些早期结构只差比例校验（例如浪3 不够长），默认不画。勾选周期栏
右侧的「放宽候选」会把它们用灰色虚线补出来，并标注「放」；它们不参与评分，也不参与
斐波那契锚点。

**斐波那契。** 按整段浪的起点→浪5 计算 0.236 / 0.382 / 0.5 / 0.618 / 0.786 回撤位；
有当前五浪时取当前，否则取最近一组，最后才退回最近波段。标签会按强弱避让，
位差太近时弱档让位给 0.382 / 0.618。

**AI 选浪。** 图表右上角的按钮会把规则枚举出的候选（最多 24 组，优先保留最近的）
连同真实转折点日期/价格、浪2/浪4 回撤、浪3 比例一起发给模型，让模型只做一件事：
**从候选编号里选出当前主数法，或判断没有可采用的结构**。模型不得发明点位；返回的
编号不在候选集合内会直接报错，不做猜测性兜底。选中后图上高亮该组、其余组变淡，
斐波那契锚点同步切换，并显示级别、起止日期、置信度与理由。AI 只改图上的主数法，
**不进入规则评分**；结果缓存 30 分钟。

**条件式交易计划。** 在同一张图上把长线和短线分开算：长线看周/月均线与周线浪型，
短线看日线浪型、日线 MA20/60 与江恩 7 循环窗口。支撑/压力不是单独取一个指标，而是把
浪型斐波那契、日/周均线、近 120 日摆动点、近期高低点和江恩锚点按 0.3 ATR 聚类，
每个价位都带来源和强度。输出只给条件：回踩哪个区间、满足什么条件才加，反弹到哪减，
收盘跌破哪里失效；没有共振支撑时会明确说"不建议在此加仓"。长线偏多、短线偏空这类
冲突会单独提示执行顺序；支撑与压力过近（不足 1 ATR 或现价 2%）时直接建议观望，
不硬凑加减仓区间。它不参与评分，也不构成买卖指令。

实测（2026-11，`deepseek-v4.1-flash`）：`sh510300` 日线枚举 3 组，模型选中当前的
小级别下降推动浪，耗时 31.8 秒；`sh510300` 日/周/月分别画出 3/9/3 组，`sh600519`
周线 13 组（前复权早期负价格问题修复后）。

## 五、开始使用

```bash
# 启动服务（Windows 双击 web/start.bat 亦可）
cd web
uvicorn app:app --host 127.0.0.1 --port 8000
```

打开 http://127.0.0.1:8000 ，四个标签页：

- **知识库检索**：按来源（书/问答/评论/社区）筛选，结果带书名与页码
- **自选盯盘**：支持分组；每只票给出规则评分、加减手数、三周期结论
- **我的持仓**：录入成本与股数，算出真实盈亏、目标仓位与相差手数
- **模拟盘**：100 万虚拟资金，按书内规则自动建仓调仓，记录净值曲线

个股详情页的 K 线会叠加小/中/大三档浪型与斐波那契回撤位；右上角「AI 选浪」会让模型在规则候选里选出主数法，只改图上的高亮与斐波那契锚点，不影响规则评分。K 线下方还有「周期与位置建议」，长线/短线分别给出加减仓区间、支撑压力与失效位。

## 七、几条设计原则

**数字不能交给模型算。** 均线、ATR、支撑位、ZigZag 转折点全部由代码计算，模型只负责把事实写成描述、把结论写成理由。提示词强制「只能使用给定数字」。

**RAG 不参与买卖决策。** 决策来自代码规则（可回测、可复现）；RAG 只负责两件事：给结论找出处、给 AI 研判提供书内依据。

**书与人的观点分层。** 书（规则）> UP 主问答与评论（个人经验）> 社区讨论（情绪）。引用时必须标明层级，UP 主给的点位必须带日期。

**不根据短期结果调参。** 模拟盘只记录不自动优化。几周的样本无法区分「规则有效」和「运气好」，调参只会把噪声当信号。

## 八、已知限制

- **回测样本短**：回测库里的日线固定约 800 根（3.2 年）、13 只 ETF；个股图会只读翻页拉长到约 1600 根用于看浪，但**不会写回回测库**。周线/月线数据有 14 年，但回测用的是日线。
- **分钟线不复权**（新浪源），跨界分红日会出现价格跳变；日/周/月为腾讯前复权。
- **AI 研判链路不可回测**：每天都要调模型，无法重跑三年。且模型即使 temperature=0 也不严格确定，已用 3 次采样多数票缓解，但仍需人工复核。
- **口语化材料检索偏弱**：问答/评论上纯 BM25 优于混合检索，尚未解决。
- **DuckDB 单写**：服务与计划任务同时复盘可能锁冲突，极端情况会失败重试。
- **接口默认无鉴权**：公网部署需自行加 API Key（`WEB_API_KEY`）或反向代理鉴权。
- **江恩书籍的图示缺失**：角度线、六角形、螺旋四方形等方法大量依赖图形，扫描件转成文字后只剩论述部分，图形本身的几何画法需要对照原书。
- **本地重排已验证不可行**：bge-reranker-base 对 20 个候选重排后，书籍召回 98%→88%、全体 85%→78%，单次耗时 4.3 秒（当前检索 30 毫秒）。质量与速度双输，未接入；评测脚本保留在 `_distill/rag/rerank_eval.py`，换模型可直接复用。
- **扫描件转写有少量拒收**：1,344 页中有 3 页被上游内容审核拒绝（普通表格页），改用本地 OCR 兜底，结果已入库。
- **多级别浪组只用于画图**：小/中/大三档扫描会提高随机走势上的假阳性，因此不参与评分；评分仍走单结构、近端、跨度与比例校验。图上的浪组应作为结构参考，不是交易信号。
- **前复权负价格**：高分红股（如茅台）长期前复权的早期价格可能为负。ZigZag 阈值已按绝对值处理，但周线全图纵轴仍会出现负价格，这是数据本身如此。
- **AI 选浪不可回测**：模型只在规则候选里做选择，点位不可编造，但选择本身无法像规则一样复现；首次调用约 30 秒，按标的与周期缓存 30 分钟。
- **交易计划是条件式输出**：它只说明"到什么价位、满足什么条件才加减"，不是买卖指令；收盘跌破/站上计划位后结构失效，应重新计算，不能把区间当成保证。
- **少数标的取数失败**：腾讯前复权接口对部分代码返回 501（实测 600036 / 300750 / 601318 / 002594），页面会显示"K线加载失败"，与浪型计算无关，需要更换数据源或重试。
